# 动态选取推荐

目标是选出当前对自己最合适的一手，并在自身收益接近时兼顾截胡。
技能和模型共用一份候选池、一个排名；右侧「本手首选」与图标上的 1 来自同一个结果。

## 使用

1. 初次识别后，在自己的玩家卡片旁选择「我的席位」。这里指选取席位，影响敌我归属与蛇形选取顺序。
2. 选到模型后选择「我的模型」；识别确认的模型归属也会参与计算。
3. 想按游戏内职责选技能时，在职责面板选择 1—5 号位；这与选取席位不同。关闭时不影响排序，自动模式只采用已经激活的推断。
4. 看「本手首选」及两个备选。每次重新识别，会去除已经选走的技能与模型并重排；自己的终极技能、普通技能和模型槽已满时，对应候选也会排除。
5. 「组合与截胡」可显示或隐藏。默认优先显示敌方已持有一半的组合；切到「历史胜率」可看本次已收录组合的胜率前十。池内与己方组合默认折叠。

前十使用更大的数字与呼吸光效，前三进一步突出。鼠标悬停显示推荐依据。
只有与首选相关的少量组合使用相同字母角标，避免整屏提示互相争抢注意力。

## 推荐指数

指数用于比较当前选择，不是本局获胜概率。以下常数是明确、可测试的启发式政策，尚未通过对局回测拟合。

### 单项基础

优先使用 Windrun 高水平胜率。若高水平场数为 n，高水平胜率为 H，总体胜率为 G：

`基础分 = 100 × [n/(n+200) × H + 200/(n+200) × G]`

总体样本包含高水平样本，因此只作为收缩目标，不把两者场数相加。
缺少高水平胜率时使用总体胜率；两者都缺失时以 45 分保守处理并注明缺统计。
有高水平胜率但场数未知时保留该胜率，同时标记证据有限；不虚构样本量。
未识别图标不参加排名。

### 自身搭配与职责

对候选与自己已有技能、模型的每条组合记录，使用 Windrun 的组合增益：

`搭配修正 = clamp(100 × 增益 × n/(n+150), -6, 6)`

样本未知时只取增益的 10%，且限制在 ±1.5 分。多个关联修正取平均，避免把重叠的相关性当作独立收益相加。缺少增益时才用组合胜率减去两个单项总体胜率的均值作近似。

控制缺口、耗蓝和技能点冲突提供小幅功能修正。职责影响限制在 ±2 分，不让人工标签压过历史数据。明确攻击类型冲突和前置条件缺失会单独降权，并复用已有的原生技能、变远程等例外；先选模型或先选技能都检查。

### 等待与截胡

平均选取顺序用于判断紧迫性，不再按 40% 当作技能强度，也不转换成「下一轮还在」的概率。同类替代明显较弱且等待较久时，最多增加 0.6 分。

「这手选完到你再选，中间隔几手」是自己相邻两手之间的间隔，不是从当前画面倒数到自己。轮次完整且时间一致时采用确认的选取记录；否则可以按自己的已选数量推算间隔，但推算不能触发自动截胡或连选承诺。

截胡改变首选需同时满足：

- 同一名敌人已持有组合的一件，另一件仍可选，且对方有合法空槽。
- 可靠轮次表明，对方在自己再下一手之前有补齐机会。
- 组合至少 100 场、历史胜率至少 58%、增益至少 6 个百分点。
- 自己拿这件也合法，且其自身推荐指数距最高分不超过 1.5 分。

已成型组合不能再被截胡；队友组合、分散在不同敌人手里的两件不能冒充敌方半套。
轮次或样本不足时仍保留组合提示，但不据此强行改首选。
确认自己可连续两手时，会比较合法双选组合；只有有足够证据的联合方案比单项方案明显更好，才显示连选搭配。

## 数据与验证边界

使用 Windrun 现有 API 返回的总体、高水平及组合统计；随应用的数据更新一并保存场数、补丁与抓取时间。场数只与同次抓取且胜率相符的记录配对，旧缓存或部分更新不会套用其他版本的场数。

本次验证覆盖推荐规则、重新识别、席位／模型／职责变更、中文展示、4K 150% 缩放及已安装应用的数据更新。统计关联不等于因果收益；实战识别仍可能漏读，缺失信息会降低建议完整性。

本地安装采用兼容补丁：更新界面、追加独立数据模块，对已安装主程序做五处可逆修改；保留识别程序及原有资源。不修改 Dota 2 文件。原安装包和本地数据库在部署前备份，备份与个人数据不上传 GitHub。
